# 2026-10-21 Session 04 — "Why should I do all this?"

## What was asked
After the Gmail setup steps (session 03), the owner asked: *"why should I do all this?"*

## Answer (summary)
**You don't have to — yet.** Without any email setup the app works fully on your own computer: every email (sign-up code, password-reset link) is printed in the terminal window, and the sign-up code is also shown on the page. That is enough to build and try every feature.

Real email is only needed when:
| Situation | Need real email? |
|---|---|
| Trying the app alone on your PC | ❌ No — read codes/links from the terminal |
| Seeing what the emails look like in a real inbox | ✅ Gmail test setup (≈5 minutes) |
| Other people testing from their own devices | ✅ Yes — they can't see your terminal |
| Going live | ✅ Yes, and with a proper provider + your own domain, not Gmail. The app refuses to start in production without it. |

Why each step exists:
| Step | Reason |
|---|---|
| 2-Step Verification | Google only offers App Passwords when it's on |
| App Password | Google blocks apps from logging in with your normal password; an App Password is limited and can be revoked on its own |
| `.env` file | Keeps the password on your computer only — never in the code or on GitHub |
| `npm run mail:test` | Checks the settings in one command instead of signing up again and again |

Recommendation given: skip it for now; come back to [[Email Sending]] when someone else needs to test, or before launch.

## Changes
None to the app. Documentation only (this note + index).

## Mistakes
None new. Lesson for future answers (recorded in `CLAUDE.md`): say up front when a step is **optional**, and why it matters, before giving long instructions.
