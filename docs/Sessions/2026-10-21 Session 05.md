# 2026-10-21 Session 05 — Fix and optimize

## What was asked
"No, skip all this [email setup] to later. Right now I just want to fix and optimize the app."

## Approach
Two tracks at the same time:
1. **Bugs:** an independent reviewer (a second AI agent with read-only instructions) read every server and client file and reproduced each suspected bug with a throw-away script. It reported 15 findings, 9 reproduced on the spot.
2. **Performance:** measure first ([[ADR-013 Performance]]): a script filled a database with 5,000 users / 30,000 requests / 20,000 conversations / 200,000 messages and timed every busy endpoint; `curl -D -` checked what the browser receives.

## What we did (in order)
1. Benchmark (after fixing [[Mistakes and Fixes#M18]]): everything 1–6 ms except the **unread counter at 25 ms**, which every user polls every 15 s → [[Mistakes and Fixes#M19]].
2. Migration 3 (6 indexes) + rewrote `OR` queries as `UNION ALL` → unread **25 → 1 ms**, inbox 3.7 → 1.5, My requests 5.6 → 1.4.
3. Delivery: JS was 316 KB uncompressed and never cached → [[Mistakes and Fixes#M20]]. Added `compression`, 1-year caching for hashed build files, `no-cache` for HTML, lazy-loaded 13 pages (fixed [[Mistakes and Fixes#M21]] on the way). First visit now 71 KB.
4. `usePolling` hook: polling pauses in hidden tabs. Conversation page: ignores late answers for a chat you've left; separate poll/send errors ([[Mistakes and Fixes#M22]]).
5. Server: skip the DB write on polls with nothing unread; `busy_timeout`, `synchronous=NORMAL`; hourly cleanup of expired sessions/codes/reset links.
6. `performance.test.js` (6 tests) → 38 pass.
7. Fixed all 15 review findings ([[Mistakes and Fixes]] M24–M35), incl. new `TRUST_PROXY` setting and per-action rate limits ([[ADR-014 Rate limiting]]), atomic KYC submit, atomic reset-link use, ban enforcement, all-or-nothing uploads (`saveFiles`).
8. `review-fixes.test.js` (13 tests). Ran them against the **old** code: 12 failed as they should; the parallel-upload one didn't ([[Mistakes and Fixes#M23]]) → bigger test files → now fails on old, passes on new.
9. Full check: **51/51 tests**, build OK, browser journey `E2E OK`, headers verified (`gzip`, `immutable`), final benchmark.
10. Found that gzip adds ~1.5–2 ms server time per list response (measured with and without); kept it because the response is ~5× smaller for phones. Recorded in ADR-013.
11. ([[Mistakes and Fixes#M17]]: `pkill` gotcha again while stopping the test server.)
