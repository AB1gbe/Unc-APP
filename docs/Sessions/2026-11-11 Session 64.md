# 2026-11-11 Session 64: Real product photos (blocked: no image credits)

## What was asked
"Use Claude to generate real product photos" (to replace the drawn pictures from [[2026-11-10 Session 62]]).

## What we found
- Claude itself writes text and code; it can't paint photos. The drawn pictures come from `scripts/make-art.mjs`.
- The connected image service (Higgsfield) can make realistic photos. A cost check said **0.25 credits per photo** (model `gpt_image_2_6`, 4:3).
- The account has **0 credits** (free plan), and free trial generations are not available. So **no photos were made and nothing was spent.**

## What it would take
About 30 photos for everything (11 demo photos, 16 categories, 3 "How it works" steps): roughly **7–8 credits**. After buying credits, ask again and the photos can be made and dropped into:
- `server/demo-photos/` (same file names), then `npm run seed` on a fresh database;
- `client/public/art/` (same file names as now).

Other ways: send your own photos (that you have the rights to), or allow a free photo site (e.g. Unsplash) on Claude's work machine.

## Then: "use Unsplash"
1. Allowed `unsplash.com` and `images.unsplash.com` in this cloud environment's network settings (the owner approved the prompt).
2. Tried Unsplash's website search from a script. Unsplash only allows automated searches through its **official API with a key**, so this was stopped ([[Mistakes and Fixes#M117]]). No photos downloaded yet.
3. Two ways forward:
   - **Free Unsplash API key** (unsplash.com/developers → New Application → copy the *Access Key*). Add it to the cloud environment: environment menu → Edit → Network secrets, host `api.unsplash.com`, header `Authorization`, value `Client-ID <your Access Key>`. Then Claude can search and download properly (and credit each photographer).
   - **No key:** on unsplash.com, right-click each photo you like → *Copy image address* (starts with `https://images.unsplash.com/photo-…`) and paste the links in the chat.

## Then: "use Pexels or free-images.com"
- **free-images.com:** allowed it in the network settings, then read its `robots.txt`: it allows only search engines and blocks all other automated tools (`User-agent: * … Disallow: /`). So it is **not used**.
- **Pexels:** the owner saved a Pexels key through the credential form (host `api.pexels.com`). The API answered **401 "Invalid API key"**. Likely cause: the form sends `Authorization: Bearer <key>`, but Pexels wants the bare key (`Authorization: <key>`), and the form can't save a key without a word in front ([[Mistakes and Fixes#M118]]).
- **Fix for the owner:** environment menu → Edit → Network secrets → the `api.pexels.com` entry → make the value just the key (no "Bearer"). Also check the key was copied whole from pexels.com/api.
