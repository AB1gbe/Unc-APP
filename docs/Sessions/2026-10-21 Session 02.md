1. Chose the email approach → [[ADR-011 Email delivery]] (SMTP via nodemailer, plus Resend API option). Installed `nodemailer@10` and, for tests, `smtp-server@3` (from the root with `--workspace server`, per [[Mistakes and Fixes#M5]]).
2. `config.js`: `APP_URL`, `MAIL_*`, `SMTP_*`, `RESEND_API_KEY`; production refuses `console` mail.
3. `db.js`: migration 2 → `password_resets` table.
4. `mailer.js` rewritten (console/memory/smtp/resend + `trySendMail`); new `emails.js` with text + HTML templates.
5. `auth.js`: emails sent via templates; `devCode` only in console mode; `forgot-password`, `reset-password/check`, `reset-password`, `change-password` → [[ADR-012 Password reset design]].
   - Self-review change: don't `await` the reset email, so response time can't reveal whether an account exists.
6. Existing 21 tests still green. Wrote `password.test.js` (8) and `mail-transports.test.js` (3, real SMTP to a local server) → **32/32 pass** on first run.
7. Client: `ForgotPassword.jsx`, `ResetPassword.jsx`, "Forgot password?" on login, change-password card on Account, email-failed warning on the code page. Build OK.
8. Real-world check: started the app with `MAIL_TRANSPORT=smtp` pointing at a local SMTP catcher; Playwright signed up (code read from the delivered email, no dev box shown), did forgot → reset → login with new password, confirmed the "password changed" email and that the used link is refused. ([[Mistakes and Fixes#M15]] scratch-script import; [[Mistakes and Fixes#M16]] false alarm on "â".)

11. Documentation (this vault).
